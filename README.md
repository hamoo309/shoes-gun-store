# SHOES GUN

هذه نسخة مصدر على الجهاز الحالي، ولا تحتوي إعدادات المتجر الخاصة أو قاعدة بياناته. تم ربط `npm.cmd run local` و`START-SHOES-GUN.cmd` بالمتجر المجهز في `../../work/shoes-gun-runtime` دون نسخ الأسرار أو البيانات هنا. افتح `../../SHOES-GUN.code-workspace` في VS Code للعمل على النسخة المجهزة بأحدث التعديلات. إذا نقلت المشروع لجهاز آخر، استخدم حزمة النقل الكاملة واستعد بياناتها؛ هذا الرابط المحلي لا ينشئ متجرًا بديلًا.

مشروع متجر أحذية يعمل بواجهة Next.js / React، وAPI مستقلة باستخدام Express وTypeScript، وقاعدة PostgreSQL حقيقية مع Prisma وMigrations. المتجر ولوحة الإدارة بالعربية وRTL، مع تبويبات التشكيلة والترتيب المطلوبة بالإنجليزية، وCheckout وتأكيد الطلب بالكامل بالإنجليزية. العملة الجنيه المصري EGP.

المرجع البصري الذي طلبه المستخدم: [تصميم STREET الأصلي](https://kickoff-sneaker-studio-oct16.jaunty-poppy-3447.chatgpt.site/). استُخدمت صور من هذا المرجع نفسه لبيانات تجربة التطوير. المنتجات وأسعارها ومخزونها وتكاليفها ورسوم الشحن بيانات تجريبية قابلة للإدارة، ويجب استبدالها أو اعتمادها قبل الإطلاق التجاري.

## تجربة المشروع محليًا

### التشغيل بعد إغلاق الجهاز وفتحه

في نسخة مجهزة مسبقًا، اضغط مرتين على **`START-SHOES-GUN.cmd`** داخل مجلد المشروع. يشغّل الملف قاعدة البيانات المحفوظة، ثم المتجر وAPI، ويتحقق من جاهزيتهما قبل فتح Chrome. إذا كان المتجر شغالًا بالفعل يفتح النسخة الموجودة. **اترك نافذة التشغيل مفتوحة أثناء الاستخدام**؛ إغلاقها أو الضغط على `Ctrl+C` يوقف المتجر المحلي. لا يحتاج هذا المسار إلى PowerShell 7 أو Codex أو VS Code.

من Terminal داخل مجلد المشروع على Windows يمكنك استعمال أمر واحد بدل الملف:

```powershell
npm.cmd run local
```

لا تُعد تشغيل `setup` أو `seed` أو إنشاء حساب الإدارة بعد كل إقلاع. البيانات والحسابات تبقى محفوظة. في أول إعداد لنسخة مصدر جديدة فقط، أكمل خطوات الإعداد أدناه ثم نفّذ `npm.cmd run build` مرة قبل استخدام ملف التشغيل. عند تعديل الكود أعد البناء أو استخدم وضع التطوير.

هذا تشغيل محلي على جهازك. يظل الجهاز قيد التشغيل أثناء استخدام الموقع؛ الإتاحة الدائمة للعملاء تحتاج نشره على خادم مستقل.

يحاول مساعد التشغيل انتظار PostgreSQL حتى تصبح قابلة للاستعلام، ويتحقق من أن الاتصال يخص مجلد قاعدة هذا المشروع. قاعدة البيانات تعمل مستقلة عن نافذة المتجر لحمايتها من إشارة `Ctrl+C`، بينما تتوقف واجهة المتجر وAPI عند إغلاق نافذة التشغيل. قد تحتاج استعادة PostgreSQL التلقائية إلى وقت بعد إغلاق غير سليم.

### الإعداد لأول مرة

المتطلبات: Node.js ‏22.12 أو أحدث متوافق، وnpm، وPostgreSQL 16. على Windows يبحث مساعد التشغيل عن `C:/Program Files/PostgreSQL/16/bin`؛ إذا اختلف المسار اضبط `PG_BIN` في `.env`. لا تأتي ملفات PostgreSQL التنفيذية داخل المشروع.

نفّذ الأوامر التالية من جذر المشروع:

```sh
npm ci
npm run setup
npm run admin:create
npm run dev
```

`setup` ينشئ `.env` خاصًا بقيم عشوائية إذا لم يكن موجودًا، ويشغّل قاعدة تطوير معزولة داخل `.local/postgres` على `127.0.0.1:55432`، ثم يولّد Prisma Client ويطبّق Migrations ويضيف Seed. لا يستبدل `.env` موجودًا، ولا يوقف خادم PostgreSQL آخر على الجهاز، ولا ينشئ مسؤولًا افتراضيًا.

`admin:create` يطلب الاسم والبريد وكلمة مرور لا تقل عن 12 حرفًا؛ إدخال كلمة المرور مخفي. ينشئ حساب مالك `SUPER_ADMIN` مع Hash من نوع scrypt، ولا يحفظ كلمة المرور الأصلية. لا تضع كلمة المرور في أمر محفوظ أو مستند تسليم. يوجد مسار `--stdin` للتشغيل الآلي عبر مدير أسرار، موضح في [دليل النشر](docs/DEPLOYMENT.md).

بعد التشغيل:

| المتجر | [http://localhost:3000](http://localhost:3000) |
| لوحة الإدارة | [http://localhost:3000/admin](http://localhost:3000/admin) |

## الإعدادات والبيانات

أوامر الجذر تقرأ `.env` من جذر المشروع وتنقل إعداداته إلى التطبيقين. ملف `.env.example` يشرح أسماء المتغيرات؛ لا تنسخ القيم الوهمية فيه إلى متجر حي. الملف الفعلي وكلمات المرور وقاعدة التطوير ومجلد التخزين والنسخ الاحتياطية مستبعدة من Git ومن حزمة المصدر.

أهم المتغيرات: `DATABASE_URL`، و`SESSION_SECRET`، و`STORAGE_DIR`، و`WEB_ORIGIN`، و`API_URL` / `API_INTERNAL_URL`، و`NEXT_PUBLIC_SITE_URL`. الشرح الكامل وإعداد HTTPS في [دليل النشر](docs/DEPLOYMENT.md). متغير `NEXT_PUBLIC_SITE_URL` له الأولوية لتوحيد Canonical وSitemap وStructured Data؛ إذا لم يُضبط يُستخدم الدومين المحفوظ في إعدادات لوحة الإدارة. يحتاج تغيير المتغير العام أو عناوين إعادة التوجيه إلى إعادة بناء Next.js.

لو عندك PostgreSQL جاهزة بدل المساعد المحلي، أنشئ `.env` أولًا بواسطة `node scripts/setup.mjs --env-only`، ثم اضبط `DATABASE_URL` الخاص بقاعدتك وشغّل:

```sh
npm run db:generate
npm run db:migrate
npm run db:seed
npm run admin:create
npm run dev
```

استخدم Seed لتجربة جديدة فقط بعد مراجعة نوع البيانات المطلوبة. يحافظ Seed على التعديلات الموجودة ولا ينشئ طلبات مبيعات وهمية أو حسابات افتراضية. يتضمن 8 منتجات تجريبية بتركيبات لون/مقاس، والتصنيفات، و27 محافظة، وإعدادات المتجر.

الصور العامة المرفوعة تُحفظ في `storage/products`، وإثباتات الدفع في `storage/private`. الإثباتات لا تُنشر كمسار صور عام، والوصول إليها يتطلب جلسة مسؤول مصرح بها. صور المنتجات المحلية تُحسّن بواسطة Next.js، بينما صور CDN الخارجية المضافة عبر HTTPS تُحمّل مباشرة في المتصفح دون تمرير عنوان خارجي إلى محسّن الخادم.

## تجربة رحلة طلب كاملة

1. افتح منتجًا واختر اللون والمقاس قبل الإضافة للسلة. عدّل الكمية من السلة ثم انتقل إلى Checkout.
2. أدخل اسمًا ورقم موبايل مصريًا وعنوانًا واضحًا، واختر المحافظة. السعر والشحن والإجمالي يُحسبون من الخادم.
3. جرّب `Cash on Delivery` ثم `Confirm Order`. تظهر صفحة خاصة تحمل Order Number، ويظهر الطلب فورًا في لوحة الإدارة.
4. جرّب طلبًا آخر باستخدام `InstaPay` إلى `01003370553`، وأدخل Transfer Reference. إثبات التحويل صورة JPEG أو PNG أو WebP اختيارية بحد 5 MB، وليس PDF.
5. من لوحة الإدارة راجع الطلب والإثبات، ثم أكد وصول التحويل أو ارفضه مع السبب. رفع الصورة أو تأكيد العميل لا يغيّر الدفع إلى Paid.
6. انقل الطلب عبر الحالات المسموحة حتى Delivered، ثم أكد تحصيل المبلغ. افحص الربح المحقق، ثم جرّب مرتجعًا جزئيًا مع الكمية والمبلغ وسياسة إعادة المخزون المناسبة.

لا يوجد اتصال مباشر ببنك أو بوابة دفع أو API من InstaPay، ولا تحويل أموال تلقائي. التحقق من التحويل والتحصيل وتسجيل رد المبلغ عمليات ينفّذها المسؤول بعد تنفيذها فعليًا. حجز المخزون يحصل عند حفظ الطلب، ويُفك عند الإلغاء أو المرتجع حسب العملية؛ لا يوجد إلغاء تلقائي للطلبات القديمة.

## لوحة الإدارة والحسابات

تدير المنتجات والصور والألوان والمقاسات والمخزون والأقسام والأسعار والتكاليف وSEO والطلبات والدفع والمرتجعات والمصروفات والشحن وإعدادات المتجر. البحث والفلاتر وتصدير CSV وسجل التغييرات متاحة. يستخدم النظام دورَي `SUPER_ADMIN` و`MANAGER`؛ إدارة حسابات المسؤولين وسجل التدقيق محمية بصلاحية المالك، ولا يمكن تعطيل آخر مالك نشط.

كلمات المرور Hash آمن، والجلسة Cookie من نوع HttpOnly وSameSite، مع فحص صلاحيات الخادم وCSRF وOrigin وRate Limiting والتحقق من الصور. في تجربة HTTP المحلية تستخدم `COOKIE_SECURE=false`؛ الإنتاج العام يحتاج HTTPS و`COOKIE_SECURE=true`.

## الحسابات المالية

جميع المبالغ داخليًا أعداد صحيحة بالقروش: `100` تعني `1.00 EGP`. يعرض الموقع ولوحة الإدارة والمخرجات المالية القيم بالجنيه المصري، ويمنع الخادم قيم الكميات والمبالغ غير الصالحة. يحفظ الطلب Snapshot لسعر البيع والخصم وتكلفة الشراء والشحن المحصل وتكلفة الشحن الفعلية.

يُعترف بالإيراد مرة واحدة بعد تحقق **التسليم والتحصيل معًا**، ويُحسب الربح من القيود التاريخية، لا من سعر المنتج الحالي. المصروفات ورسوم الدفع ورد المبالغ وتكلفة الشحن الفعلية تدخل الحساب. يعالج قيد المرتجع عكس تكلفة البضاعة المُعادة إلى المخزون ويربط الاسترداد بالقيود المحققة دون خصم البيع مرتين. `cashRefunds` يعرض المبالغ المردودة فعليًا بتاريخها، مع فصلها عن أثرها المحاسبي على إيراد معترف به.

التقارير تميّز عدد الطلبات **المنشأة** عن الربح **المحقق** في الفترة، وتستخدم `Africa/Cairo` وبداية فترة مشمولة ونهاية غير مشمولة. تشمل يومًا وأسبوعًا وشهرًا وسنة وAll Time وفترة مخصصة. يظهر تحذير صريح إذا غابت تكلفة شراء أو تكلفة شحن تاريخية؛ يكون الربح عندها غير مكتمل.

للنسخ الاحتياطي: [دليل النسخ والاستعادة](docs/BACKUP.md). النسخة تشمل PostgreSQL والوسائط العامة والخاصة، مع الاحتفاظ بسر الجلسة منفصلًا. جرّب الاستعادة في قاعدة معزولة قبل الإطلاق.

### معاينة خلفية على Windows

بعد إعداد قاعدة البيانات وبناء المشروع يمكنك تشغيل نسخة إنتاج محلية في الخلفية باستخدام `npm run preview:start`، وفحصها بـ`npm run preview:status` وإيقافها بـ`npm run preview:stop`. تتطلب هذه الأوامر PowerShell 7، وتتحقق من هوية العملية قبل إيقافها. لا توقف خدمة PostgreSQL الأخرى على الجهاز. للتشغيل الأمامي المعتاد استخدم `npm start` ثم `Ctrl+C`.
