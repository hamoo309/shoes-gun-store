## اختبارات التكامل

الملف القابل لإعادة التشغيل هو [integration.test.mjs](../tests/integration.test.mjs)، من خلال `npm test`. ينشئ المساعد Schema عشوائية تبدأ بـ`sg_test_` ويطبّق Migrations وSeed ويشغّل API اختبار مستقلة، ثم يزيل Schema وملفات إثباتاتها. لا يستعمل طلبات المتجر أو مخزونه الفعلي للاختبار.

تغطي الحالات الـ26:

- الفهرس العام و27 محافظة وعدم تسريب تكلفة الشراء أو تكلفة الشحن الفعلية أو بيانات الدخول.
- Quote من أسعار الخادم والشحن حسب المحافظة، وتجاهل سعر أو إجمالي يرسله العميل.
- رفض بيانات العميل والهاتف والكمية والمحافظة غير الصالحة دون تغيير المخزون.
- طلب COD، وتطبيع `+20`، وحفظ البيانات، وطلبين متزامنين بمفتاح واحد ينتجان طلبًا واحدًا وحجزًا واحدًا؛ رفض إعادة استخدام المفتاح لمحتوى مختلف.
- حماية صفحة الطلب برمز وصول، وعدم عرض الملاحظات الداخلية والتكاليف، والتنافس على آخر قطعة دون بيع زائد.
- حماية APIs بالمصادقة وCSRF وOrigin، والبحث والفلاتر وظهور الطلب الفوري والملاحظات وانتقالات الحالات.
- طلب InstaPay، ورفض ملف مزيف، وحفظ صورة سليمة خاصة، ومنع عرضها للعامة؛ بقاء الدفع Pending Verification بعد الرفع.
- رفض تحويل بسبب مطلوب، ثم تأكيده من مسؤول، وفصل الدفع عن التوصيل.
- عدم الاعتراف بإيراد COD عند التسليم وحده، واستعمال لقطات الأسعار والتكاليف والشحن بعد تعديل بيانات المنتج والمحافظة.
- منع الاعتراف المكرر والتحصيل المكرر، ومرتجع جزئي وكامل مع منع زيادة الاسترداد أو إعادة المخزون مرتين.
- أثر المصروفات، والاسترداد قبل إلغاء طلب مدفوع، وحدود الفترات بتوقيت القاهرة والتحذير من تكلفة تاريخية ناقصة.
- CSV بالجنيه المصري مع تحييد خلايا الصيغ، وفحص الصور العامة وحد الحجم، وتعطيل محافظة، وCRUD المنتجات والأقسام والأرشفة.
- صلاحيات المدير والمالك وسجل التدقيق وحماية آخر مالك نشط، واختبار CLI إنشاء مسؤول عبر stdin مع تخزين scrypt فقط وعدم طباعة كلمة المرور.

## مثال مالي تم التحقق منه

طلب يحتوي قطعتين بسعر 1,299 EGP للقطعة، وتكلفة شراء 720 EGP للقطعة، وشحن محصل 60 EGP وتكلفة شحن فعلية 45 EGP:

| المرحلة | صافي الربح المحقق EGP |
| --- | ---: |
| قبل اجتماع التسليم والتحصيل | 0.00 |
| بعد التسليم والتحصيل | 1,173.00 |
| بعد رد قطعة ورد سعرها وإعادتها للمخزون | 594.00 |
| بعد رد القطعة الأخرى والشحن المحصل بالكامل | -45.00 |
| بعد إضافة مصروف 12.50 EGP | -57.50 |

بقيت تكلفة الشحن الفعلية خسارة بعد الاسترداد الكامل، ولم يُخصم الخصم أو الاسترداد مرتين. تُقيد الإيرادات والعكس في تاريخ تحققها، وتبقى لقطات الطلب ثابتة بعد تغيير بيانات المنتج الحالي. الأسبوع يبدأ يوم الاثنين؛ الفترات تبدأ عند منتصف ليل القاهرة وتشمل البداية وتستثني النهاية.

## تجربة المتصفح والاستجابة

تمت تجربة اختيار اللون والمقاس وإلزامهما، وتعديل كمية السلة، وحقول التحقق الإنجليزية، وتبديل الشحن بين الإسكندرية والقاهرة، وإنشاء طلب InstaPay حقيقي داخل قاعدة التطوير باسم **TEST ONLY — Browser QA**. ظهرت صفحة النجاح ورقم الطلب والإجمالي الصحيح، ثم ظهر الطلب في لوحة الإدارة. جرى تسجيل رفض التحويل بسبب اختبار وإلغاء الطلب؛ أعيد المخزون المحجوز. لم يُنفّذ تحويل مالي أو شحن حقيقي.

اجتازت واجهة الموبايل البحث والتصنيف والترتيب والمفضلة. جرى فحص صفحات المتجر والمنتج وCheckout ولوحة الإدارة في متصفح Chromium باستخدام إطارات بعروض 390 و768 و1440 بكسل. تساوى `scrollWidth` مع `clientWidth`، مع استثناء عرض شريط التمرير الرأسي، ولم يظهر تمرير أفقي للصفحة. تظهر تبويبات التشكيلة الستة في صفين على الموبايل. هذه معاينة بأحجام أجهزة داخل المتصفح، وليست تجربة على أجهزة فعلية.

## إعادة التشغيل والحدود المتبقية

أُضيف `START-SHOES-GUN.cmd` و`npm.cmd run local` لتشغيل قاعدة البيانات والمتجر بعد إعادة فتح الجهاز دون الاعتماد على PowerShell المرفق مع Codex. جرى التحقق بإيقاف خادم المتجر وقاعدة التطوير بالكامل ثم تشغيلهما بالمسار الجديد من مجلد عمل مختلف. أعاد المتجر والإدارة وفحص الصحة HTTP 200، وتطابقت أعداد المنتجات والطلبات والمسؤولين وتركيبات المخزون وبصمة كميات المخزون قبل الإيقاف وبعد التشغيل. جرى كذلك تشغيل ملف CMD مع PATH لا يحتوي على Codex أو PowerShell 7، وإعادة الضغط أثناء عمل المتجر دون إنشاء خادم مكرر. هذه محاكاة لإيقاف العمليات وإعادة تشغيلها؛ لم يُعد تشغيل Windows نفسه أثناء التحقق.

اتبع [README](../README.md) ثم شغّل `npm test` و`npm run build`. لا يتطلب إنشاء مسؤول كلمة مرور ثابتة أو حسابًا افتراضيًا. حساب مسؤول فحص المتصفح مؤقت وأُبطل بعد التحقق، ولا تتضمن حزمة المصدر قاعدة التطوير أو أسرارها.

تعليمات Docker وCaddy وHTTPS قابلة للتنفيذ على المضيف المقصود، لكن تشغيل الحاويات نفسه لم يُختبر هنا. يلزم إدخال بيانات المنتجات والتكلفة والمخزون وأسعار الشحن الحقيقية والدومين والسياسات قبل الإطلاق. تكاليف العمليات التي لم يتحقق إيرادها، مثل شحن طلب ملغى، تُسجّل كمصروف عند تكبدها؛ لا يُفترض أن تكلفة الشحن المخططة تعني دفعها فعليًا.
