# التشغيل والنقل والنشر بعد توحيد المشروع

## مجلد العمل الوحيد

افتح مجلد `SHOES-GUN` الذي يحتوي `package.json` و`apps` و`scripts`، أو افتح ملف مساحة العمل الموجود بجانبه. الواجهة في `apps/web` وAPI في `apps/api` داخل هذا الجذر نفسه. لا تختَر نسخة من أرشيف التاريخ، ولا تنسخ واجهة قديمة فوق الجديدة.

## الجهاز الحالي

```powershell
npm.cmd run local
```

المتجر `http://localhost:3000` والإدارة `http://localhost:3000/admin`. يمكن تشغيل `START-SHOES-GUN.cmd` بدل الأمر. تبقى نافذة التطبيق مفتوحة، ويعاد الأمر بعد إعادة فتح الجهاز. المتطلبات: Node.js 22.12 أو أحدث وPostgreSQL 16. ملفات المتجر التنفيذية المبنية مولدة من هذا المصدر، ولا يعتمد التشغيل على Codex أو نسخة مشروع أخرى.

لإعادة تثبيت المكتبات بعد إيقاف التطبيق:

```powershell
npm.cmd ci --include=dev
npm.cmd run db:generate
npm.cmd run typecheck
npm.cmd run lint
npm.cmd run build
npm.cmd run local
```

لا تعِد إعداد متجر موجود بواسطة `setup` أو `db:seed`. `.env` و`.local/postgres` و`storage` بيانات خاصة دائمة؛ لا تُحذف لحل مشكلة بناء. عند تحريك المشروع أوقف التطبيق وPostgreSQL بشكل سليم أولًا، أو استخدم حزمة النقل المنطقية المستقلة عن مسار PostgreSQL.

## النقل إلى جهاز جديد

1. ثبت Node.js 22.12 أو أحدث وPostgreSQL 16، مع اتصال إنترنت أول مرة لتنزيل الاعتماديات.
2. فك `SHOES-GUN-FULL-TRANSFER.zip` في مكان جديد، وافتح مجلد `SHOES-GUN` الناتج.
3. شغّل `RESTORE-FIRST.cmd`. يتحقق من الملفات، ويستعيد إلى قاعدة جديدة منفصلة فقط، ويقارن كل الصفوف والصور قبل تطبيق الهجرة الإضافية وبناء الموقع.
4. بعد ذلك استعمل `START-SHOES-GUN.cmd`، وحساب الإدارة الحالي. [دليل الاستعادة والتكرار والمنافذ](../README-TRANSFER.md).

حزمة النقل خاصة لأنها تضم البيانات والإعدادات. حزمة `SHOES-GUN-SOURCE.zip` عامة من حيث خلوها من ملفات التشغيل الخاصة والقاعدة والصور المرفوعة؛ هي مصدر للتطوير والبناء وليست نسخة بيانات متجر.

## اختبارات معزولة قابلة للنقل

`npm test` يشغّل 25 حالة أمان وحواجز تشغيل آمنة، بعد بناء API. `npm run lint` يفحص الأنواع والاستيرادات والمتغيرات المحلية غير المستخدمة بواسطة TypeScript؛ لم يُضف ESLint أو مدقق React Hooks.

اختبارات API الأوسع تحتاج نسخة بيانات منفصلة مستعادة في مجلد مختلف، ولا يجوز توجيهها إلى هذا المتجر. يجهّز المشغّل داخل النسخة المعزولة `.local/isolated-test.json` يحتوي:

```json
{
  "purpose": "SHOES_GUN_ISOLATED_TEST",
  "databaseName": "NAME_OF_ISOLATED_RESTORED_DATABASE",
  "databasePort": 55446,
  "webPort": 3016,
  "apiPort": 4016,
  "authApiPorts": [4010, 4011, 4012],
  "dataDirectory": "ABSOLUTE_QA_PROJECT_PATH/.local/postgres"
}
```

العلامة وحدها لا تكفي للسماح بالكتابة. `tests/isolated-qa.mjs` يرفض جذر المشروع الرئيسي ومنافذ المتجر، ويتحقق قراءةً فقط من `.env` والمسارات الحقيقية وملكية ملفات PostgreSQL واستعلام `SHOW data_directory` واسم القاعدة والمنفذ. قبل أي طلب HTTP معدّل تُثبت الاختبارات اتصال API بنفس القاعدة باستخدام قيمة عشوائية مخصصة للاختبار.

من المشروع الرئيسي، بعد تشغيل خدمات النسخة المعزولة وتطبيق الهجرة المطلوبة عليها، يحدد المشغّل `SHOES_GUN_QA_ROOT` لاختبارات الطلبات، أو `SECURITY_QA_ROOT` مع `DATABASE_URL` الخاص بالنسخة لاختبارات الدخول. استخدم `npm run test:orders:isolated` و`npm run test:auth:isolated`. لا تطبع قيم الاتصال أو بيانات الاختبار الحساسة. لم تعد الاختبارات مرتبطة بمسار جهاز أو مجلد تاريخي معين.

## نشر الواجهة الحالية على Vercel

المشروع يتكون من واجهة وخادم API وقاعدة PostgreSQL ووسائط دائمة. نشر `apps/web` وحده يعرض الواجهة، لكنه لا ينقل إعدادات البانر والفوتر أو المنتجات أو الحسابات من قاعدة الجهاز.

1. جهّز خادم API وقاعدة PostgreSQL وتخزينًا دائمًا للوسائط، واستعد أحدث لقطة إلى هدف جديد متحقق منه، مع الحفاظ على حسابات المتجر وأسراره الثابتة.
2. التطبيق الحالي يرفع الصور على قرص الخادم. يمكن إبقاء API على خادم ذي قرص دائم؛ نقله إلى بيئة Functions يحتاج تكييف التخزين العام والخاص. لا تستخدم التخزين المؤقت لحفظ صور المتجر.
3. في إعدادات Vercel يختار المشروع `apps/web` كـRoot Directory، مع إتاحة مكتبات Workspaces من جذر المستودع بحسب إعداد المشروع. عين `API_URL` و`API_INTERNAL_URL` إلى أصل HTTPS العام لخدمة API، دون إضافة `/api` في نهاية القيمة، و`NEXT_PUBLIC_SITE_URL` إلى أصل الواجهة الصحيح.
4. على API اضبط أصول المتجر المطابقة وHTTPS وCookies الآمنة وحد الدخول PostgreSQL والصلاحيات المحدودة وفق [دليل الإنتاج](DEPLOYMENT.md).
5. ابنِ وانشر إصدارًا جديدًا بعد تعديل متغيرات Vercel؛ افحص `/api/health` و`/api/settings` و`/api/products`، ثم البانر والصور وتسجيل الدخول والطلبات على بيئة تجربة.

لا تضع `localhost` أو اسم خدمة Docker الداخلي `api` كوجهة عامة لـVercel. الخطأ `DNS_HOSTNAME_RESOLVED_PRIVATE` الذي ظهر في النسخة السابقة سببه وجهة Rewrite خاصة غير قابلة للوصول. [مرجع Vercel](https://vercel.com/docs/errors/dns_hostname_resolved_private)، و[تطبيق تغييرات البيئة على النشر الجديد](https://vercel.com/docs/environment-variables).

يوجد أيضًا خيار النشر المتكامل بـDocker/Caddy موضح في [DEPLOYMENT.md](DEPLOYMENT.md) و[خطة الانتقال](PRODUCTION-PREPARATION.md). يتطلب التحقق من الحاويات وTLS على المضيف المستهدف. لم يُنفذ نشر أو تعديل إعدادات استضافة أثناء توحيد الملفات.
