# ترتيب أقسام الرئيسية ومتابعة الشحن وإصلاح التشغيل — 21 أكتوبر 2026

## أماكن الإعدادات وطريقة الاستخدام

من لوحة الإدارة افتح **ترتيب أقسام الرئيسية**، أو `/admin?view=homepage-layout`. تظهر أقسام التشكيلة الحالية، بما فيها All وCasual وSports وFashion وBest Sellers وHot Deals والتصنيفات التي تضيفها. استخدم ↑ و↓ لنقل أي قسم، ومفتاح الإظهار لإخفائه أو إظهاره، ثم اضغط **حفظ ترتيب الأقسام**. المعاينة تتغير قبل الحفظ؛ حدّث صفحة المتجر بعد الحفظ لرؤية النتيجة على الكمبيوتر والموبايل.

يمكن نقل قسم جديد قبل Hot Deals وجعل Best Sellers آخر قسم. الترتيب الحالي هو الافتراضي حتى تحفظ اختيارًا آخر. التصنيفات الجديدة تدخل القائمة مرة واحدة، وتظل التصنيفات والمنتجات محفوظة عند إخفاء قسم من الرئيسية. التصنيف غير المفعّل لا يظهر للزوار حتى تعيد تفعيله من «الأقسام». إخفاء جميع أقسام الرئيسية لا يمنع فتح صفحة «كل المنتجات».

من **الطلبات → متابعة الطلبات والشحن** تظهر الحالات السبع مع الأعداد والفلاتر: بانتظار التأكيد، مؤكد، قيد التجهيز، تم الشحن، تم التسليم، ملغي، مرتجع. افتح تفاصيل الطلب لتغيير الحالة وإضافة رقم تتبع الشحنة. القائمة تعرض كل الحالات، وتوضح الحالات غير المتاحة حاليًا.

المسار المعتاد: **بانتظار التأكيد ← مؤكد ← قيد التجهيز ← تم الشحن ← تم التسليم**. الإلغاء متاح حسب حالة الطلب والدفع، والمرتجع يُسجل من نموذج **المرتجعات والاستردادات** بعد التسليم، مع تحديد القطع والمبالغ. يظل تأكيد التحصيل إجراءً مستقلًا؛ تغيير الشحن لا يؤكد الدفع تلقائيًا ولا يكرر خصم المخزون أو إعادته. أسماء الحالات موحدة بالعربية في الإدارة وصفحة متابعة العميل، مع عرض رقم التتبع عند تسجيله.

## السبب الفعلي والتغيير

ترتيب أزرار أقسام التشكيلة كان مكتوبًا في `standardTabs` داخل الواجهة، ثم تضاف التصنيفات المخصصة في النهاية. أصبح الترتيب والظهور محفوظين في سجل `Setting.homepageSections` بقاعدة البيانات، مع تحقق الإدارة وCSRF ومنع المفاتيح المكررة أو غير الموجودة. لم يحتج التحديث تغيير مخطط قاعدة البيانات أو تطبيق migrations.

كانت حالات الطلب السبع موجودة أصلًا في قاعدة البيانات. قائمة التغيير كانت تحصر العرض في الحالة الحالية والخطوة التالية والإلغاء، ولذلك ظهر نحو ثلاثة خيارات. أصبحت الحالات كلها مرئية، مع الإبقاء على قواعد الانتقال ومنع تجاوز إجراء المرتجع. أضيفت أعداد جميع الحالات باستعلام مستقل يراعي البحث والتاريخ والدفع والمحافظة، وتُحدّث الأعداد بعد التعديل.

عطل التشغيل المرصود كان `P1001`: PostgreSQL المحفوظة كانت متوقفة، بينما أوامر `dev` و`start` والمعاينة تبدأ API والواجهة مباشرة. أضيف فحص مشترك يشغل القاعدة المحفوظة وينتظر اتصالها قبل بدء التطبيق. التشغيل المعتاد يرفض إنشاء قاعدة بديلة فارغة عند فقد البيانات. التفاصيل في [دليل التشغيل](STARTUP-2026-10-21.md).

## التشغيل والتسليم

افتح مجلد المشروع الذي يحتوي `package.json` في VS Code، ثم:

```powershell
npm.cmd run local
```

اترك النافذة مفتوحة. افتح `http://localhost:3000` للمتجر و`http://localhost:3000/admin` للإدارة. بعد إعادة تشغيل الجهاز شغّل الأمر أو `START-SHOES-GUN.cmd` مجددًا. لبناء التعديلات استخدم **`npm.cmd run build` من جذر المشروع** حتى تُحمّل إعدادات الاتصال والمنافذ الخاصة قبل بناء الواجهة.

على جهاز جديد استخدم ملف **SHOES-GUN-FULL-TRANSFER.zip** كاملًا، وفكّه في مجلد جديد، ثم شغّل `RESTORE-FIRST.cmd` أول مرة. الحسابات والصور والطلبات تنتقل مع لقطة البيانات. وقت اللقطة وبصماتها مسجلان في `transfer/manifest.json`، ونتائج فحص الحزمة في `docs/TRANSFER-VERIFICATION.md` داخل نسخة النقل. الأرشيف الكامل خاص لأنه يتضمن بيانات المتجر وإعداداته السرية.
