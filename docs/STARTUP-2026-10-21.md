# تحديث التشغيل من VS Code — 21 أكتوبر 2026

## السبب الذي ظهر في الفحص

كانت أوامر الجذر `npm run dev` و`npm start` و`npm run preview:start` تطلق التطبيق دون تشغيل قاعدة PostgreSQL المحفوظة أو انتظار اتصالها. كان `npm run local` وحده يقوم بهذه الخطوة. بعد توقف القاعدة أو إعادة فتح الجهاز، يمكن أن تفتح الواجهة وتفشل طلبات البيانات برسالة Prisma `P1001` على `127.0.0.1:55432`.

عند بدء الفحص لم تكن منافذ المتجر 3000 وAPI ‏4000 والقاعدة المعزولة 55432 تستمع. سجّل آخر تشغيل للقاعدة في 20 أكتوبر جاهزية واستعلامات ناجحة ثم إنهاء عملية مساعدة بالكود `0xC000013A` وطلب إيقاف. لا يكفي هذا السجل وحده لإثبات أن ملفات الكود أو بيانات PostgreSQL تالفة، ولا يحدد وحده إن كان الإغلاق من التيرمينال أو إغلاق Windows. خدمة PostgreSQL الأخرى على 5432 ليست قاعدة هذا المشروع ولم يستهدفها الإصلاح.

## التغيير

- أُضيف فحص مشترك `scripts/app-preflight.mjs` قبل تشغيل تطبيقَي المتجر وAPI من `dev` و`start` و`local`. معاينة الخلفية تستخدم `start` وبالتالي تمر بالفحص نفسه.
- القاعدة المحلية المحفوظة تُشغّل بواسطة المساعد الموجود، مع انتظار جاهزية الاستعلام والتحقق من هوية مجلدها. بقي عزل PostgreSQL عن نافذة التطبيق على Windows كما هو.
- مسارات تشغيل التطبيق تستعمل خيار `--existing-only`: إذا كانت القاعدة المحفوظة مفقودة أو غير مكتملة، أو غابت قاعدة المتجر داخلها، تتوقف بأمان دون إنشاء بديل فارغ. تبقى رسائل إصلاح البيانات موجهة لاستعادة النسخة الحالية أو إكمال النقل.
- يُنفذ `SELECT 1` على قاعدة التطبيق قبل إطلاق الخادمين. للاتصال الخارجي المُدار خارج المشروع، الفحص للقراءة فقط ولا ينشئ قاعدة أو يشغّل خدمة.
- التشغيل لا يطبق Migrations ولا Seed ولا يكتب `.env`. بقي مساعد إنشاء نسخة جديدة اليدوي واستعادة ملف النقل يعملان وفق مسارهما السابق.

## التحقق المنفذ على حواجز التشغيل

نجحت 9 حالات في `node --test tests/local-startup.test.mjs`، دون أي اتصال بقاعدة المتجر أو تشغيل PostgreSQL أو Seed. الاختبارات تستخدم مجلدات مؤقتة، وتتحقق من ثبات بصمات الملفات وعدم طباعة كلمة مرور الاختبار، وتشمل:

- غياب الإعدادات الخاصة أو الاعتماديات مع رسالة إصلاح مناسبة.
- غياب الإعدادات قبل إطلاق الخادمين من `dev` و`start`.
- وجود ملفات قاعدة محفوظة دون `PG_VERSION` في كل من `local` و`dev` و`start`؛ تُحفظ الملفات ولا تعمل الخوادم أو أدوات إنشاء القاعدة.
- رفض تشغيل قاعدة مفقودة في وضع `--existing-only` دون إنشاء مجلدات جديدة.

نتائج التشغيل الحقيقي وترقية الخصائص والنسخ الاحتياطي والنقل تُسجل مع تقرير تحديث المشروع بعد إكمال التحقق على النسخة المعزولة والنسخة المستخدمة.

## الاستخدام

افتح مجلد المشروع الذي يحتوي `package.json` في VS Code، ثم من Terminal:

```powershell
npm.cmd run local
```

اترك النافذة مفتوحة وافتح `http://localhost:3000` أو `/admin`. يمكن الضغط مرتين على `START-SHOES-GUN.cmd` بدل الأمر. عند تعديل الكود استخدم `npm.cmd run dev` للتطوير، أو أعد البناء ثم شغّل النسخة الإنتاجية. لا تشغّل طريقتين على المنفذين نفسيهما في وقت واحد.

على جهاز جديد، أكمل أولًا استعادة ملف النقل الكامل بواسطة `RESTORE-FIRST.cmd` أو `node scripts/restore-transfer.mjs`؛ التشغيل المعتاد لا ينشئ متجرًا جديدًا إذا كانت البيانات لم تُستعد بعد. لا يوجد تشغيل تلقائي مع Windows؛ أعد تشغيل الأمر أو الملف بعد فتح الجهاز. إغلاق النظام يوقف خدماته المحلية، حتى لو كانت القاعدة معزولة عن إشارة نافذة التطبيق.
