# SHOES GUN — النسخة الكاملة للنقل، 23 أكتوبر 2026

هذه الحزمة نسخة خاصة من المتجر تشمل أحدث المصدر، ونسخة PostgreSQL المنطقية، وكل الصور والوسائط وإثباتات الدفع الخاصة، وملف الإعدادات الأصلي. تحتوي على بيانات العملاء وأسرار المتجر؛ احتفظ بها في مكان خاص ولا ترفعها إلى مستودع أو رابط عام.

## النقل إلى جهاز Windows آخر

1. ثبّت **Node.js 22.12 أو أحدث** شاملًا npm، و**PostgreSQL 16**. يلزم اتصال بالإنترنت لتنزيل الاعتماديات. لا يلزم Codex أو VS Code أو PowerShell 7.
2. فك ZIP في **مجلد جديد**. لا تنسخه فوق نسخة متجر مجهزة أو قاعدة بيانات موجودة.
3. افتح مجلد `SHOES-GUN` واضغط مرتين على **RESTORE-FIRST.cmd**. يفحص الحزمة، يثبت الاعتماديات، ينشئ قاعدة منفصلة داخل هذا المجلد، يستعيد البيانات والوسائط ويتحقق منها، ثم يطبّق الترحيل الإضافي ويبني التطبيق ويفتح المتجر.
4. استخدم بريد الإدارة وكلمة المرور الحاليين. بعد ذلك يكفي **START-SHOES-GUN.cmd** لكل تشغيل. اترك نافذة التطبيق مفتوحة أثناء الاستخدام؛ يغلق `Ctrl+C` التطبيق، بينما تبقى قاعدة البيانات المحلية محفوظة.

المنافذ الافتراضية هي قاعدة البيانات `55432`، والمتجر `3000`، وAPI `4000`. المتجر ولوحة الإدارة محليًا على `http://localhost:3000` و`http://localhost:3000/admin`. الاتصال بقاعدة النسخة المستعادة مربوط بـ`127.0.0.1` فقط. ملف التشغيل المحلي يفعّل استثناء HTTP المحلي الصريح؛ الإعدادات هنا مخصصة للتجربة المحلية، والإتاحة العامة تحتاج إعداد خادم وHTTPS منفصلين.

إذا كان PostgreSQL 16 مثبتًا في مسار مختلف أو كانت المنافذ مستخدمة، شغّل من PowerShell داخل هذا المجلد، مع اختيار منافذ متاحة:

```powershell
$env:PG_BIN = 'C:/Program Files/PostgreSQL/16/bin'
$env:SG_RESTORE_DB_PORT = '55443'
$env:SG_RESTORE_WEB_PORT = '3013'
$env:SG_RESTORE_API_PORT = '4013'
.\RESTORE-FIRST.cmd
```

عند اختيار منافذ المثال، افتح المتجر على `http://localhost:3013` ولوحة الإدارة على `http://localhost:3013/admin`. لا يوقف المساعد عملية أخرى ليفرغ منفذًا مستخدمًا. يجب أن تكون أدوات `initdb` و`pg_ctl` و`pg_restore` كلها إصدار 16؛ يفحص المساعد الإصدار فعليًا قبل إنشاء إعدادات القاعدة الجديدة.

## التحقق فقط دون استعادة

لفحص SHA-256 لملفات النسخة الخاصة وملفات المصدر المسجلة في `transfer/manifest.json`، استخدم أحد الأمرين:

```powershell
.\RESTORE-FIRST.cmd --verify
node scripts/restore-transfer.mjs --verify
```

يعمل هذا الفحص باستخدام Node وحده، قبل تثبيت الاعتماديات، ولا يحتاج PostgreSQL ولا ينشئ `.env` أو قاعدة أو وسائط أو يشغّل التطبيق. يكشف الملفات الخاصة الناقصة أو الزائدة والملفات المسجلة التي تغير محتواها؛ لا يغني عن الاحتفاظ بالحزمة الأصلية في مكان موثوق.

## ما الذي يُحفظ وكيف تُستأنف المحاولة؟

يبقى `transfer/environment.env` الأصلي كما هو داخل الحزمة. يحتفظ المساعد باسم مستخدم PostgreSQL وكلمة مروره و`SESSION_SECRET` و`APP_SECRET` إن كان موجودًا، ويغيّر عناوين الاتصال والمنافذ ومسارات التخزين للنسخة المحلية فقط. يحتفظ كذلك بحسابات الإدارة وHashes كلمات المرور والجلسات والطلبات والمخزون والإعدادات والقيود المالية. لا يعرض الأسرار أو عنوان اتصال القاعدة في المخرجات.

تتم الاستعادة داخل قاعدة جديدة فارغة فقط، دون أوامر حذف للجداول. قبل تطبيق أي Migration، تقارن الأداة عدد الصفوف وSHA-256 لمحتوى **كل جدول public** مع لقطة النقل، بما فيها `_prisma_migrations`. تستخدم البصمة تنسيق `pg-json-utc-c-v1`، مع توقيت UTC وتنسيق تاريخ ISO وترتيب نصي `C` لضمان تطابقها بين الأجهزة. ترفض الأداة لقطة لا تعلن هذا التنسيق قبل إجراء أي تغيير. بعد التحقق تُنسخ كل الوسائط العامة والخاصة، ويُنشأ `.local/transfer-restored.json` مرة واحدة. يأتي ترحيل `AuthLoginAttempt` الإضافي بعد هذا التحقق: يضيف جدولًا فارغًا وسجل Migration؛ لذلك اختلاف عدد الجداول وسجل الترحيلات بعد التحديث متوقع، ولا تعاد مقارنة قاعدة مستخدمة بلقطة قديمة.

إذا انقطع التثبيت أو الاستعادة **قبل إنشاء علامة التحقق**، فك الحزمة الأصلية في مجلد جديد وأعد المحاولة؛ اترك المجلد السابق للفحص ولا تحذف بيانات متجر آخر. إذا انقطع الترحيل أو البناء **بعد إنشاء العلامة**، أعد تشغيل `RESTORE-FIRST.cmd`: يتحقق من أن القاعدة تخص هذا المجلد ومن هويتها، ثم يكمل الترحيل ويعيد بناء التطبيق لهذه النسخة المحلية، دون إعادة الاستعادة أو استبدال الوسائط أو كتابة العلامة فوق القديمة. يُعاد البناء في كل استدعاء للاستعادة حتى تتوافق ملفات التطبيق مع إعدادات النسخة المحلية الحالية.

ملف `RESTORE-FIRST.cmd` يعزل متغيرات التطبيق والاتصال الموروثة من نافذة الأوامر حتى تقرأ هذه النسخة `.env` الصحيح. عند تشغيل `START-SHOES-GUN.cmd` لاحقًا، استخدم نافذة لا تفرض قيمًا أخرى لـ`DATABASE_URL` أو المنافذ أو الأسرار أو `UPLOAD_DIR` على مستوى الجهاز.

لا تشغّل `setup` أو `db:seed` أو reset أو إنشاء مسؤول جديد لنقل متجر موجود. لا توجد كلمة مرور إدارة افتراضية في الحزمة. لا تنشر هذه الحزمة الخاصة كما هي.
